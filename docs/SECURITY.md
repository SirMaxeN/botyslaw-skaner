# Security and data handling

Capture starts only after user action and Android MediaProjection consent. A visible overlay and foreground notification provide stop controls. Frame analysis and OCR run locally. Full-resolution screen captures and sampled inventory frames remain in memory during analysis and are not uploaded or included in releases. Local setup can retain normalized counter/list/navigation geometry and coarse 32 × 64 grayscale layout signatures with selected regions masked out; these references stay on the device and can be removed with calibration settings.

Optional Discord pairing exchanges a short-lived one-use code for a device credential. AndroidKeyStore protects the stored credential. Synchronization sends reviewed resource numbers over HTTPS to the fixed backend origin. No Discord bot token is bundled in the app. The local demo simulates pairing and sending without contacting the backend or updating a real clan.

Automatic read optionally uses an AccessibilityService after a separate disclosure and explicit user activation in Android settings. It receives window-state package/class metadata to restrict bounded navigation and scroll gestures to the foreground game. It cannot retrieve accessibility window contents. Every scan is user-started; leaving the game, locking the device, stopping capture or pressing STOP revokes its gesture session. An already dispatched short gesture may finish. The route contains no purchase, summon, forge or merge action. Manual read works without this service.

The app does not request microphone, root, contacts, SMS, broad storage or package-installation permissions. ML Kit SDK data disclosures are described in the public privacy policy; local screen processing does not imply that every dependency is telemetry-free.

Google Play builds query official Play update availability and offer to open the app listing in Google Play. They do not start an SDK download or installation flow. Google documents device metadata, application version and installed module/asset-pack information used by this request; see the [Play update data-safety documentation](https://developer.android.com/guide/playcore/in-app-updates#data-safety) and [Google privacy policy](https://policies.google.com/privacy). Do not describe this SDK processing as anonymous without evidence. Website builds may offer an update link that opens in the browser after user action. The scanner does not silently download or install executable updates.

Production signing material belongs only in ignored `.signing/`. Keep a separate private backup. Never upload signing keys, local pairing data, private fixtures, account setup history or server credentials to Git or public download directories. Only intentional public store screenshots belong in `docs/play-console/assets/`.

Run `python tools/check_repository.py` before committing. It checks Git's actual candidate files for excluded artifacts and common credential patterns without printing matched secret values. This is a guard against accidental disclosure, not a security certification.
